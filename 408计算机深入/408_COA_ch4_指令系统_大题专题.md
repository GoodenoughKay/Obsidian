## §1 指令系统基本概念

### 指令的组成

$$\underbrace{\text{操作码（OP Code）}}_{指令做什么} \quad \underbrace{\text{地址码（Address Field）}}_{操作数在哪里}$$

**操作码**：告诉 CU（控制器）执行什么操作（加法、跳转、加载等）。

**地址码**：指定操作数的位置（内存地址、寄存器号、立即数等）。

### 按地址码个数分类（选择题必考）

| 类型 | 格式 | 含义 | 典型指令 |
|------|------|------|---------|
| 零地址指令 | OP | 无操作数或操作数隐含 | `NOP`（空操作）、`HLT`（停机）、堆栈机的 `PUSH/POP` |
| 一地址指令 | OP + A1 | 单操作数，或隐含使用 ACC | `INC A1`（自增）、`NOT A1` |
| 二地址指令 | OP + A1 + A2 | 目的操作数 + 源操作数 | `ADD A1, A2`（A1 = A1 + A2） |
| 三地址指令 | OP + A1 + A2 + A3 | 两个源 + 一个目的 | `ADD A1, A2, A3`（A1 = A2 + A3） |

### 指令字长与机器字长

| 概念 | 含义 |
|------|------|
| 机器字长 | CPU 一次处理的数据宽度（ALU 位数） |
| 指令字长 | 一条指令的二进制位数 |
| 存储字长 | 存储器一次读写的数据宽度 |
| 定长指令字 | 所有指令等长，便于流水线（RISC 常用） |
| 变长指令字 | 指令可长可短，编码密度高但取指复杂（CISC 常用）|

## §2 操作码扩展技术（大题计算考点）

### 核心思想

指令字长固定时，用**不同长度的操作码**适配不同数量的地址码：
- 地址码多（三地址）→ 操作码位数少（短 OP）
- 地址码少（零地址）→ 操作码位数多（长 OP）

**关键规则**：短操作码的某些编码作为"扩展标志"，留给下一级更长的操作码使用。

### 大题计算公式

设指令字长为 $N$ 位，每个地址码为 $d$ 位，各级指令条数为 $n_i$：

$$\text{各级可用编码总数} = 2^N$$

$$\text{某级已用编码占用的} 2^N \text{个中的份额} = n_i \times 2^{N - k_i}$$

其中 $k_i$ 为第 $i$ 级操作码的位数。

零地址指令数 = $2^N - \sum_{i \neq 0} n_i \times 2^{N-k_i}$

---

### 大题典型例题 1：操作码扩展设计（16 位指令字）

**题目**：指令字长 16 位，每个地址码 4 位，设计操作码扩展方案，使得：
- 三地址指令 15 条
- 二地址指令 15 条
- 一地址指令 15 条
- 零地址指令尽可能多，共几条？

**解答**：

**第一步：确定各级操作码位数**

| 指令类型 | 操作码位数 = 16 - 地址码总位数 |
|---------|-------------------------------|
| 三地址 | $16 - 3 \times 4 = 4$ 位 |
| 二地址 | $16 - 2 \times 4 = 8$ 位 |
| 一地址 | $16 - 1 \times 4 = 12$ 位 |
| 零地址 | $16 - 0 \times 4 = 16$ 位 |

**第二步：分配编码（从短到长，每级留出扩展标志）**

- 三地址（4 位 OP）：用 $0000 \sim 1110$ 共 15 条，$1111$ 留作扩展标志
- 二地址（8 位 OP）：高 4 位固定为 $1111$，低 4 位用 $0000 \sim 1110$ 共 15 条，$1111\ 1111$ 留作扩展标志
- 一地址（12 位 OP）：高 8 位固定为 $1111\ 1111$，低 4 位用 $0000 \sim 1110$ 共 15 条，$1111\ 1111\ 1111$ 留作扩展标志
- 零地址（16 位 OP）：高 12 位固定为 $1111\ 1111\ 1111$，低 4 位全用 $0000 \sim 1111$ 共 16 条

**第三步：计算零地址指令数**

$$\text{零地址指令数} = 2^{16} - 15 \times 2^{12} - 15 \times 2^{8} - 15 \times 2^{4}$$
$$= 65536 - 61440 - 3840 - 240 = \boxed{16 \text{ 条}}$$

> 也可直接从扩展标志处往下推：零地址共 16 条（$1111\ 1111\ 1111\ 0000 \sim 1111\ 1111\ 1111\ 1111$）。

---

### 大题典型例题 2：操作码扩展计算（12 位指令字）

**题目**：指令字长 12 位，每个地址码 3 位。三地址指令 4 条，二地址指令 8 条，一地址指令 12 条，求零地址指令最多几条。

**解答**：

各级操作码位数：
- 三地址：$12 - 9 = 3$ 位
- 二地址：$12 - 6 = 6$ 位
- 一地址：$12 - 3 = 9$ 位
- 零地址：$12 - 0 = 12$ 位

零地址指令数：
$$= 2^{12} - 4 \times 2^9 - 8 \times 2^6 - 12 \times 2^3$$
$$= 4096 - 2048 - 512 - 96 = \boxed{1440 \text{ 条}}$$

---

### 答题步骤模板（操作码扩展）

1. 列表：各类型指令 → 操作码位数 = 指令字长 - 地址码总位数
2. 从短到长分配编码，每级留最后若干种编码作扩展标志
3. 零地址指令数 = $2^N - \sum n_i \times 2^{N - k_i}$
4. 验证：各级占用编码数之和 ≤ $2^N$

## §3 寻址方式（最高频考点，8 种必须全背）

### 八种寻址方式速查表

| 寻址方式 | 有效地址 EA | 操作数位置 | 访存次数 | 典型用途 |
|---------|-----------|-----------|---------|---------|
| 立即寻址 | 操作数 = $A$（A 不是地址） | 指令本身 | 0 | 常数赋值（`MOV R0, #5`） |
| 直接寻址 | $EA = A$ | 内存 $M[A]$ | 1 | 访问固定地址变量 |
| 间接寻址 | $EA = M[A]$ | 内存 $M[M[A]]$ | 2（单级） | 扩大地址空间；指针 |
| 寄存器寻址 | $EA = R_A$（寄存器） | 寄存器 $(R_A)$ | 0 | 高速运算（`ADD R0, R1`） |
| 寄存器间接寻址 | $EA = (R_A)$ | 内存 $M[(R_A)]$ | 1 | 指针操作 |
| 基址寻址 | $EA = (BR) + A$ | 内存 $M[(BR)+A]$ | 1 | 程序重定位、多道程序 |
| 变址寻址 | $EA = (IX) + A$ | 内存 $M[(IX)+A]$ | 1 | 数组遍历、循环 |
| 相对寻址 | $EA = (PC) + A$ | 内存 $M[(PC)+A]$ | 1 | 跳转指令（位置无关代码） |

> ⚠️ **立即寻址 vs 直接寻址**：立即寻址中 $A$ 是操作数本身（数值），直接寻址中 $A$ 是操作数的地址。

### 基址寻址 vs 变址寻址（高频混淆点）

| 对比项 | 基址寻址 | 变址寻址 |
|--------|---------|---------|
| 公式 | $EA = (BR) + A$ | $EA = (IX) + A$ |
| 固定的量 | $A$（程序内偏移，编译时确定） | $A$（数组基地址，编译时确定） |
| 变化的量 | $BR$（基址寄存器，OS 设置） | $IX$（变址寄存器，程序员/编译器控制） |
| 用途 | 程序重定位，实现多进程地址隔离 | 数组遍历，循环访问连续内存 |

### 相对寻址中 PC 的值（踩坑！）

$$EA = (PC) + A$$

取指令时 PC **已经自增**指向下一条指令，所以跳转目标是相对于**下一条指令**的偏移，不是当前指令！

> 例：当前指令在地址 200H，PC 已自增为 204H（假设指令 4 字节），偏移 $A = 10H$，则 $EA = 204H + 10H = 214H$。

### 大题典型例题 3：寻址方式综合分析

**题目**：设 PC = 200H，某指令位于地址 200H，形式地址 $A = 400H$。已知：内存 $[400H] = 600H$，内存 $[600H] = 99$，寄存器 R1 = 400H，变址寄存器 IX = 200H。

判断下列各情况属于哪种寻址方式，并写出操作数的值和访存次数：

| 情况 | 操作数 | 寻址方式 | 访存次数 |
|------|--------|---------|---------|
| 操作数 = $400H$（A 本身当数值用）| $400H$ | **立即寻址** | 0 |
| 操作数 = $M[400H]$ = $600H$ | $600H$ | **直接寻址** | 1 |
| 操作数 = $M[M[400H]]$ = $M[600H]$ = $99$ | $99$ | **间接寻址** | 2 |
| 操作数 = $(R1)$ = $400H$，再取 $M[400H]$ = $600H$ | $600H$ | **寄存器间接寻址** | 1 |
| $EA = (IX) + A = 200H + 400H = 600H$，操作数 = $M[600H]$ = $99$ | $99$ | **变址寻址** | 1 |
| PC 已自增为 204H，$EA = 204H + 400H = 604H$ | $M[604H]$ | **相对寻址** | 1 |

### 大题典型例题 4：有效地址计算

**题目**：某机器字长 32 位，寄存器 R0 = 1000H，R1 = 200H，变址寄存器 IX = 50H，PC = 300H（取指后已自增为 304H）。指令地址码 $A = 100H$。分别计算以下寻址方式的有效地址 EA：

(a) 直接寻址
(b) 寄存器间接寻址（R0）
(c) 基址寻址（BR = R1）
(d) 变址寻址（IX）
(e) 相对寻址（PC 已为 304H）

**解答**：

| 寻址方式 | 计算过程 | EA |
|---------|---------|-----|
| (a) 直接 | $EA = A$ | $100H$ |
| (b) 寄存器间接 | $EA = (R0) = 1000H$ | $1000H$ |
| (c) 基址 | $EA = (R1) + A = 200H + 100H$ | $300H$ |
| (d) 变址 | $EA = (IX) + A = 50H + 100H$ | $150H$ |
| (e) 相对 | $EA = (PC) + A = 304H + 100H$ | $404H$ |

## §4 数据的对齐与大/小端存放

### 大端（Big-Endian）vs 小端（Little-Endian）

以 32 位整数 $\text{0x12345678}$ 存放在内存地址 1000H 开始为例：

| 字节地址 | 大端存放 | 小端存放 |
|---------|---------|---------|
| 1000H | 12（最高字节） | 78（最低字节） |
| 1001H | 34 | 56 |
| 1002H | 56 | 34 |
| 1003H | 78 | 12（最低字节） |

**记忆口诀**：
- **大端**：高字节存低地址（数的"大头"在前）
- **小端**：低字节存低地址（数的"小头"在前）

**代表**：
- 大端：MIPS、SPARC、网络字节序（TCP/IP）
- 小端：x86、ARM（可配置）

### 数据对齐

**对齐规则**：$n$ 字节的数据，其起始地址必须是 $n$ 的整数倍。

| 数据类型 | 大小 | 对齐要求 | 例：合法地址 |
|---------|------|---------|------------|
| char | 1 字节 | 无要求 | 0, 1, 2, 3, ... |
| short | 2 字节 | 2 的倍数 | 0, 2, 4, 6, ... |
| int / float | 4 字节 | 4 的倍数 | 0, 4, 8, 12, ... |
| double | 8 字节 | 8 的倍数 | 0, 8, 16, ... |

**为什么需要对齐**：现代 CPU 读取内存按固定宽度（如 4 字节/8 字节），对齐的数据一次读取即可，不对齐需要两次读取并拼接，性能下降。

### 大题典型例题 5：结构体内存布局与大/小端

**题目**：以下 C 结构体在 32 位小端机器上的内存布局是什么？起始地址为 1000H。

```c
struct S {
    char  a;    // 1 字节
    int   b;    // 4 字节
    short c;    // 2 字节
};
```

**解答**：

按对齐规则（各成员对齐到自身大小的整数倍地址）：

| 地址 | 内容 | 说明 |
|------|------|------|
| 1000H | `a` | char，1 字节，无对齐要求 |
| 1001H～1003H | （填充 padding） | 为使 `b` 从 4 的倍数地址开始 |
| 1004H～1007H | `b` | int，4 字节，地址 1004H 是 4 的倍数 ✓ |
| 1008H～1009H | `c` | short，2 字节，地址 1008H 是 2 的倍数 ✓ |
| 100AH～100BH | （末尾填充） | 结构体整体大小需为最大成员（4字节）的倍数 |

结构体总大小 = **12 字节**（不是 7 字节！因为有填充）。

> ⚠️ 小端存放：若 `b = 0x12345678`，则地址 1004H 处存 78，1005H 存 56，1006H 存 34，1007H 存 12。

## §5 CISC vs RISC（高频选择题）

### 对比表（必背）

| 特性 | CISC（复杂指令集）| RISC（精简指令集）|
|------|-----------------|-----------------|
| 全称 | Complex Instruction Set Computer | Reduced Instruction Set Computer |
| 指令数量 | 多（几百条） | 少（几十条） |
| 指令长度 | **变长** | **定长**（通常 32 位） |
| 寻址方式 | 多种复杂寻址 | 少（寄存器 + 基址为主） |
| 访存操作 | 运算指令可直接访存 | **只有 Load/Store 访存**，其余只操作寄存器 |
| 通用寄存器 | 少（x86 早期只有 8 个） | 多（32 个） |
| 控制器类型 | 微程序控制器（复杂指令难硬连线）| 硬连线控制器（简单指令，速度快）|
| 流水线 | 难以流水（变长指令） | **易于流水**（定长，各阶段均匀）|
| 代表 | Intel x86（PC/服务器） | ARM（手机）、MIPS（路由器）、RISC-V |

### 最重要的区别（必背）

**RISC 的 Load/Store 结构**：内存访问只能通过专用的 Load（读）和 Store（写）指令，所有运算指令只在寄存器之间操作。

```
RISC 的加法（两步）:
    LW  R1, [1000H]     # 先把内存的数取到寄存器
    ADD R0, R0, R1      # 再做加法

CISC 的加法（一步）:
    ADD R0, [1000H]     # 直接对内存操作数做加法
```

## §6 高级语言程序与机器代码的对应

### 编译器、汇编器、链接器

| 工具 | 输入 | 输出 | 作用 |
|------|------|------|------|
| 编译器（Compiler） | 高级语言源码（.c） | 汇编语言（.s） | 将高级语言翻译成汇编 |
| 汇编器（Assembler） | 汇编语言（.s） | 目标文件（.o，机器码） | 将汇编翻译成机器码 |
| 链接器（Linker） | 多个目标文件（.o）+ 库 | 可执行文件 | 合并目标文件，解析符号引用 |

### 选择结构（if-else）的机器级表示

```c
if (a > b) {
    c = a - b;
} else {
    c = b - a;
}
```

对应汇编（MIPS 风格）：

```assembly
BLE R1, R2, ELSE    # 若 R1 ≤ R2（即 a ≤ b），跳转到 ELSE
SUB R3, R1, R2      # c = a - b
J   END             # 跳过 else 分支
ELSE:
SUB R3, R2, R1      # c = b - a
END:
```

### 循环结构（for/while）的机器级表示

```c
int sum = 0;
for (int i = 0; i < 100; i++) {
    sum += i;
}
```

对应汇编：

```assembly
MOV R1, #0         # sum = 0
MOV R2, #0         # i = 0
LOOP:
BGE R2, #100, END  # 若 i ≥ 100，退出循环
ADD R1, R1, R2     # sum += i
ADD R2, R2, #1     # i++
J   LOOP           # 继续循环
END:
```

### 过程（函数）调用的机器级表示

函数调用需要解决：保存返回地址、传递参数、保存寄存器现场、返回值传递。

**调用约定（Call Convention）**：

| 约定 | 说明 |
|------|------|
| 参数传递 | 前几个参数用寄存器传（如 MIPS：$a0～$a3），多余参数压栈 |
| 返回值 | 存入指定寄存器（如 MIPS：$v0） |
| 返回地址 | 存入 $ra（MIPS）或压栈 |
| 调用者保存寄存器 | 调用前自行保存（$t0～$t9） |
| 被调用者保存寄存器 | 函数内使用前必须先保存（$s0～$s7） |

**函数调用完整流程**：

```
调用方：
  1. 把参数写入 $a0～$a3
  2. jal FUNC          # 跳转并把返回地址存入 $ra

被调用函数：
  3. 将 $ra、$s 系列寄存器压栈保存
  4. 执行函数体
  5. 将返回值写入 $v0
  6. 恢复 $ra 和 $s 系列
  7. jr $ra            # 跳回调用方

调用方：
  8. 从 $v0 取返回值继续执行
```

### 大题典型例题 6：读懂汇编 → 还原 C 代码

**题目**：阅读以下 MIPS 汇编代码，写出对应的 C 语言等价程序（R1 = n，R2 = result）：

```assembly
MOV R2, #1       # result = 1
MOV R3, #1       # i = 1
LOOP:
BGT R3, R1, END  # if (i > n) goto END
MUL R2, R2, R3   # result = result * i
ADD R3, R3, #1   # i++
J   LOOP
END:
```

**解答**：

```c
int result = 1;
for (int i = 1; i <= n; i++) {
    result = result * i;
}
// 最终 result = n!（n 的阶乘）
```

## 附：大题答题要点总结

### 题型一：操作码扩展（计算指令条数）

**答题步骤**：
1. 列表：每类指令的操作码位数 = 指令字长 − 地址码总位数
2. 从短操作码开始分配，每级用掉若干编码（留最后若干种作扩展标志）
3. 套公式：零地址数 = $2^N - \sum n_i \times 2^{N-k_i}$
4. 验证不超出总编码数

### 题型二：寻址方式辨析（判断 EA 和访存次数）

**答题步骤**：
1. 看公式：立即（A 本身）→ 0 次；寄存器（R）→ 0 次；其余 → 1 次；间接 → 2 次
2. 注意基址 vs 变址的区别（前者 OS 改 BR，后者程序改 IX）
3. 相对寻址：$EA = (PC) + A$，PC 已是**下一条**指令地址（取指后自增）

### 题型三：大/小端判断

**答题步骤**：
1. 大端：高字节存低地址（最高有效字节在最小地址）
2. 小端：低字节存低地址（最低有效字节在最小地址）
3. 逐字节填入内存表格

### 题型四：汇编代码分析

**答题步骤**：
1. 识别分支（B 系列）和跳转（J/JMP）指令 → 对应 if/while/for
2. 识别函数调用（JAL/CALL）和返回（JR $ra / RET）
3. 从汇编逆推控制流，还原高级语言结构

## 常见误区速查

| 误区 | 正确理解 |
|------|---------|
| 基址寻址和变址寻址是同一回事 | 公式相同但用途不同：基址由 OS 改动实现重定位，变址由程序改动实现数组遍历 |
| 相对寻址中 PC 是当前指令地址 | 取指后 PC 已自增，指向**下一条**指令；EA 相对于下一条指令计算 |
| 间接寻址只有 1 次访存 | 单级间接需 **2 次**访存：第 1 次取地址，第 2 次取数据 |
| 立即寻址有 1 次访存 | 操作数在指令中，**不需要额外访存**（取指时已获得） |
| RISC 比 CISC 指令多 | 恰好相反：RISC 指令**少**（精简），CISC 指令**多**（复杂） |
| 结构体大小 = 各成员大小之和 | 因为**对齐填充（padding）**，实际大小 ≥ 成员大小之和 |

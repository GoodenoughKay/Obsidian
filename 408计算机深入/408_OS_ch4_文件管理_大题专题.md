## §1 文件的基本概念

**文件（File）**：具有文件名的一组相关信息的集合，是外存存储的基本单位。

**文件系统的四大功能**：

| 功能 | 说明 |
|------|------|
| 文件管理 | 文件的创建、删除、读写、重命名 |
| 目录管理 | 维护目录（文件名 → 文件位置的映射） |
| 存储空间管理 | 磁盘块的分配与回收 |
| 文件共享与保护 | 多进程共享文件，访问权限控制 |

**文件的分类**（按性质）：

| 类型 | 说明 | 例子 |
|------|------|------|
| 普通文件 | 用户数据文件 | `.txt`、`.exe`、`.jpg` |
| 目录文件 | 内容是目录项的特殊文件 | 每个文件夹本身就是一个文件 |
| 设备文件 | 将 I/O 设备映射为文件 | `/dev/sda`（磁盘）、`/dev/tty`（终端）|
| 管道文件 | 进程间通信用的特殊文件 | Unix 的命名管道（FIFO）|

## §2 文件元数据与 inode（高频考点）

### 文件控制块（FCB）

操作系统为每个文件维护的数据结构，记录文件的所有**元数据（metadata）**：

| 类别 | 字段 |
|------|------|
| 基本信息 | 文件名、文件类型、创建/修改/访问时间 |
| 存储信息 | 文件大小、物理位置（起始块号或索引块地址）、存储方式 |
| 访问控制 | 文件所有者、访问权限（读/写/执行）|
| 使用信息 | 被哪些进程打开、引用计数（硬链接数） |

### inode（Index Node）

Unix/Linux 中 FCB 的具体实现。

> ⚠️ **最重要的特性：inode 不包含文件名！**

文件名存在**目录项**中，目录项的内容是：`文件名 → inode 号` 的映射。

inode 只存储：
- 文件类型、权限、所有者、大小、时间戳
- 数据块地址（直接块 + 各级间接块）
- 硬链接计数（link count）

**设计好处**：一个 inode 可以对应多个文件名（硬链接），文件名只是指向 inode 的指针，删除文件名不一定删除数据（要等 link count 归零）。

### inode 多级索引结构（大题核心）

Unix inode 采用**混合索引**，兼顾小文件和大文件：

```
inode：
  ├── 直接块 × 12      → 直接指向数据块
  ├── 一级间接块 × 1   → 间接块 → 数据块
  ├── 二级间接块 × 1   → 间接块 → 间接块 → 数据块
  └── 三级间接块 × 1   → 间接块 → 间接块 → 间接块 → 数据块
```

**设块大小 = $B$ 字节，每个块号占 $k$ 字节，则每个间接块可存 $N = B/k$ 个块号**：

| 索引级别 | 可寻址块数 | 覆盖文件大小 |
|---------|-----------|-------------|
| 直接块（12个） | $12$ 块 | $12 \times B$ |
| 一级间接 | $N$ 块 | $N \times B$ |
| 二级间接 | $N^2$ 块 | $N^2 \times B$ |
| 三级间接 | $N^3$ 块 | $N^3 \times B$ |
| **合计最大文件** | $12 + N + N^2 + N^3$ 块 | — |

**例**：块大小 1 KB，块号 4 B，则 $N = 1024/4 = 256$：

| 级别 | 块数 | 大小 |
|------|------|------|
| 直接块 | 12 | 12 KB |
| 一级间接 | 256 | 256 KB |
| 二级间接 | $256^2 = 65536$ | 64 MB |
| 三级间接 | $256^3 \approx 1.6 \times 10^7$ | 16 GB |

### 大题典型例题 1：inode 访问次数计算

**题目**：文件系统磁盘块大小 1 KB，块号占 4 B，inode 含 12 个直接块、1 个一级间接块、1 个二级间接块、1 个三级间接块。inode 已在内存，求访问文件逻辑块号 **268** 需要几次磁盘访问？

**解答**：

**第一步：计算每个间接块能存的块号数**

$$N = \frac{1024}{4} = 256$$

**第二步：划分各级范围**

| 级别 | 逻辑块号范围 |
|------|------------|
| 直接块 | $0 \sim 11$（共 12 块）|
| 一级间接 | $12 \sim 267$（共 256 块）|
| 二级间接 | $268 \sim 268 + 256^2 - 1 = 268 \sim 65803$ |
| 三级间接 | $65804 \sim \ldots$ |

**第三步：确定逻辑块 268 属于哪级**

$268 \geq 268$，属于**二级间接**范围。

**第四步：计算访问次数**

访问路径（inode 已在内存，不算）：

1. 读**一级间接块**（找到二级间接块地址）→ 1 次
2. 读**二级间接块**（找到数据块地址）→ 1 次
3. 读**数据块** → 1 次

**共需 3 次磁盘访问。**

---

### 大题典型例题 2：inode 访问次数（inode 也在磁盘）

**题目**：同上配置，但 inode **也在磁盘**（未缓存）。访问逻辑块号 10 需几次磁盘访问？

**解答**：

逻辑块 10 属于**直接块**范围（$0 \sim 11$）。

1. 读 inode（找到直接块地址）→ 1 次
2. 读数据块 → 1 次

**共需 2 次磁盘访问。**

> 📌 **关键**：题目一定要先看"inode 是否在内存"，在内存则不算，在磁盘则 +1 次。

---

### 答题步骤模板（inode 访问次数）

1. 计算 $N = \text{块大小} / \text{块号大小}$
2. 列出各级范围：直接（$0 \sim 11$）、一级（$12 \sim 11+N$）、二级（$12+N \sim 11+N+N^2$）、三级（以此类推）
3. 判断目标逻辑块号落在哪一级
4. 访问次数 = 间接级数 + 1（数据块）+ （inode 在磁盘则再 +1）

## §3 文件的操作

| 操作 | 说明 | 系统调用 |
|------|------|---------|
| 建立（Create） | 分配 inode 和目录项，初始化元数据 | `creat()` / `open(O_CREAT)` |
| 删除（Delete） | 减少 link count，归零时释放 inode 和数据块 | `unlink()` |
| 打开（Open） | 将文件 inode 载入内存，返回文件描述符 fd | `open()` |
| 关闭（Close） | 释放文件描述符，更新元数据 | `close()` |
| 读（Read） | 从当前文件指针位置读数据 | `read()` |
| 写（Write） | 向当前文件指针位置写数据 | `write()` |

### 打开文件的数据结构（选择题考点）

进程打开文件后，内核维护三张表：

```
进程 A                   内核                      磁盘
┌──────────┐     ┌─────────────────┐     ┌──────────────┐
│ 文件描述符 │────▶│  打开文件表      │────▶│ inode（元数据）│
│ fd = 3   │     │  (file offset,  │     │ + 数据块     │
└──────────┘     │   inode 指针)   │     └──────────────┘
                 └─────────────────┘
```

- **文件描述符表（fd table）**：每个进程一张，fd 是索引
- **打开文件表（open file table）**：内核全局，存文件偏移量（读写位置）和 inode 指针
- **inode 表（v-node 表）**：内核全局，缓存磁盘上的 inode

> ⚠️ 两个进程打开同一个文件：各有独立的 fd 和打开文件表项（各自的读写偏移），但共享同一个 inode。

## §4 文件的保护

### Unix 权限模型（rwx）

Unix 将用户分三类：**所有者（Owner）/ 组（Group）/ 其他人（Others）**，每类分配 r/w/x 三位权限。

权限字符串示例 `-rwxr-xr--`：

```
- rwx r-x r--
│ │   │   └── 其他用户：只读（r--）
│ │   └────── 同组用户：读+执行（r-x）
│ └────────── 文件所有者：读+写+执行（rwx）
└──────────── 文件类型：- 普通文件，d 目录，l 软链接
```

对应八进制：`rwxr-xr-- = 111 101 100 = 754`

### 访问控制方式

| 方式 | 原理 | 优缺点 |
|------|------|--------|
| 访问控制矩阵 | 行=用户，列=文件，格=权限 | 灵活但存储代价大 |
| 访问控制列表（ACL） | 每个文件维护用户→权限的列表 | 灵活，Linux 扩展权限用此 |
| 权限位（Unix rwx） | 简化版 ACL，三类用户各 3 位 | 简单，Unix/Linux 默认方式 |

## §5 文件的逻辑结构

**无结构文件（流式文件）**：内容是字节流，OS 不解析内部结构，由应用程序负责（如 `.txt`、`.jpg`）。

**有结构文件（记录式文件）**：

| 类型 | 说明 | 举例 |
|------|------|------|
| 顺序文件 | 记录按顺序排列，只能顺序读写 | 磁带文件、日志文件 |
| 索引文件 | 每条记录有键，通过索引定位任意记录 | 数据库文件 |

> 📌 408 对逻辑结构以概念理解为主，重点在**物理结构**（§6）。

## §6 文件的物理结构（大题核心考点）

物理结构描述文件数据**在磁盘上的实际存储方式**。

### 三种物理结构对比

| 特性 | 连续分配 | 链接分配 | 索引分配 |
|------|---------|---------|---------|
| 顺序访问 | 快 | 慢（需逐块跟指针）| 快 |
| 随机访问 | 快（起始块号 + 偏移）| 不支持（隐式）/ 慢（FAT）| 快（查索引块）|
| 外部碎片 | **有** | 无 | 无 |
| 内部碎片 | 无 | 无 | 小（索引块可能未满）|
| 文件动态增长 | 困难 | 容易 | 容易 |
| 代表系统 | CD-ROM | FAT12/16/32 | Unix ext2/3/4 |

### 连续分配

文件存储在**连续的磁盘块**中。

目录项记录：`（起始块号，块数）`

随机访问第 $i$ 块：物理块号 = 起始块号 + $i$，**无需额外访存**。

缺点：产生外部碎片，文件扩展时可能需要整体移动。

### 链接分配

#### 隐式链接（块内存指针）

每个数据块末尾存指向下一块的指针：

```
块5 → [数据][→块12] → 块12 → [数据][→块3] → 块3 → [数据][→NULL]
```

只支持**顺序访问**，不支持随机访问（访问第 $n$ 块需从头遍历）。

#### 显式链接（FAT）

把所有块的链接指针集中存在内存的**文件分配表（FAT）**中：

```
FAT 表（驻留内存）：
块号 │ 下一块
  5  │  12
 12  │   3
  3  │  -1（EOF）
```

支持在内存中快速查找，但 FAT 表本身占用内存（磁盘越大越占内存）。

### 索引分配（inode，重点见 §2）

为每个文件建立**索引块**，存放所有数据块的物理块号。随机访问第 $i$ 块：读索引块第 $i$ 项，一次即可。

采用多级索引（见 §2）支持超大文件。

---

### 大题典型例题 3：物理结构对比分析

**题目**：某文件系统磁盘块大小 512 B，文件 F 共 5 块，数据在块号 3、7、10、15、22（按逻辑顺序）。

(a) 用连续分配，目录项记录什么？访问逻辑块 3 需几次磁盘访问？

(b) 用隐式链接分配，访问逻辑块 3 需几次磁盘访问？

(c) 用索引分配（索引块在块号 50，inode 在内存），访问逻辑块 3 需几次磁盘访问？

**解答**：

**(a) 连续分配**

前提：连续分配要求块连续，但题目给出的是离散块，**不能直接用连续分配**（此为反例）。若能连续，目录项记录 `（起始块号 = 3，块数 = 5）`，访问逻辑块 3：物理块 = 3 + 3 = 6，**1 次**磁盘访问。

**(b) 隐式链接**

访问逻辑块 3（第 4 块，从 0 开始计），需从第 0 块出发遍历：块3 → 块7 → 块10 → 块15，需读前 4 块才到第 4 块：**4 次**磁盘访问。

**(c) 索引分配**

1. 读索引块（块 50），找到逻辑块 3 对应的物理块号 = 15 → 1 次
2. 读数据块 15 → 1 次

**共 2 次磁盘访问。**

## §7 目录结构

**目录（Directory）**：一种特殊的文件，内容是 `文件名 → inode 号` 的映射表。

### 目录结构演进

| 类型 | 说明 | 缺点 |
|------|------|------|
| 单级目录 | 全系统只有一个目录 | 文件名不能重复，管理混乱 |
| 两级目录 | 主目录 + 每用户子目录 | 用户间文件名可同名，但无层次 |
| 树形目录 | 多级，现代 OS 标准 | 共享文件需要在多处建目录项 |
| 有向无环图（DAG）目录 | 树形 + 共享（同一文件可有多个父目录）| 实现复杂，需引用计数 |

### 树形目录路径

- **绝对路径**：从根目录 `/` 开始，如 `/home/user/doc.txt`
- **相对路径**：从当前工作目录开始，如 `../parent/file`

### 路径解析（目录查找）磁盘访问次数

以访问 `/a/b/c.txt` 为例（inode 均不在内存，每个目录项和 inode 各需 1 次访问）：

| 步骤 | 操作 | 磁盘访问 |
|------|------|---------|
| 1 | 读根目录 `/` 的 inode | 1 次 |
| 2 | 读根目录数据块，找到 `a` 的 inode 号 | 1 次 |
| 3 | 读 `a` 的 inode | 1 次 |
| 4 | 读 `a` 目录数据块，找到 `b` 的 inode 号 | 1 次 |
| 5 | 读 `b` 的 inode | 1 次 |
| 6 | 读 `b` 目录数据块，找到 `c.txt` 的 inode 号 | 1 次 |
| 7 | 读 `c.txt` 的 inode | 1 次 |
| 8 | 读 `c.txt` 数据块 | 1 次 |

**共 8 次磁盘访问**（每深一级目录多 2 次）。

> 📌 **规律**：路径深度为 $d$（从根算文件为第 $d$ 级），磁盘访问次数 = $2d$（每级读 inode + 读目录数据块），最后再加 1 次读文件数据块 = $2d + 1$ 次（根目录 inode 不单独算则减 1，视题目假设）。

## §8 硬链接与软链接（高频考点）

### 硬链接（Hard Link）

在某目录下创建一个新目录项，指向**同一个 inode 号**。

```
目录项 A："file.txt" → inode 100
目录项 B："link.txt" → inode 100   ← 硬链接
```

特点：
- inode 的 link count + 1
- 删除任意一个文件名，link count - 1；**只有 link count 归零时才真正删除数据**
- 硬链接与原文件**完全等价**，不分主次
- **不能跨文件系统**（不同文件系统的 inode 号相互独立）
- **不能指向目录**（防止目录树出现环路）

### 软链接（Symbolic Link / 符号链接）

创建一个特殊文件，其内容是**目标文件的路径字符串**。

```
目录项："shortcut" → inode 200（软链接文件）
inode 200 的内容："/home/user/file.txt"（路径字符串）
```

特点：
- 软链接有**独立的 inode**，是一个独立的文件
- 访问软链接时，OS 先读软链接内容（路径），再跳转到目标路径解析
- 删除原文件后，软链接**变为悬空链接（dangling link）**，访问报错
- **可以跨文件系统**
- **可以指向目录**

### 硬链接 vs 软链接对比（必背）

| 对比项 | 硬链接 | 软链接 |
|-------|-------|-------|
| 本质 | 同一 inode 的另一个目录项 | 存储路径字符串的独立文件 |
| inode 数量 | 共用一个 inode | 各自独立的 inode |
| 删除原文件 | 数据仍在（link count > 0） | 软链接变为悬空链接 |
| 跨文件系统 | **不能** | **可以** |
| 指向目录 | **不能** | **可以** |
| 访问速度 | 直接访问（无需二次解析）| 需额外解析路径（慢一步）|
| Unix 命令 | `ln file link` | `ln -s file link` |

## §9 文件系统全局结构（Layout）

### 外存中的文件系统结构

磁盘分区格式化后，文件系统的布局（以 ext2 为例）：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 引导块   │ 超级块   │ 块组描述符│ inode 表 │ 数据块区  │
│ Boot     │ Superblock│ BGD      │ inode 表 │ Data     │
└──────────┴──────────┴──────────┴──────────┴──────────┘
```

| 区域 | 内容 |
|------|------|
| 引导块（Boot Block） | 操作系统引导程序（仅第一个分区有效）|
| 超级块（Superblock） | 文件系统元数据：总块数、空闲块数、inode 总数、块大小等 |
| 块组描述符（Block Group Descriptor） | 每个块组的 inode 表位置、块位图位置等 |
| inode 位图（inode Bitmap） | 哪些 inode 已被使用 |
| 块位图（Block Bitmap） | 哪些数据块已被使用 |
| inode 表（inode Table） | 所有 inode 的存储区 |
| 数据块区（Data Blocks） | 文件和目录的实际数据 |

### 内存中的文件系统结构

OS 将常用结构缓存在内存中：

| 内存数据结构 | 内容 |
|------------|------|
| 超级块缓存 | 文件系统全局信息 |
| inode 缓存 | 最近使用的 inode（减少磁盘访问）|
| 目录项缓存（dentry cache）| 最近解析的路径（减少路径解析开销）|
| 页缓存（Page Cache）| 文件数据块的内存缓冲区 |

### 虚拟文件系统（VFS）

VFS 是内核中的文件系统**抽象层**，为上层提供统一的接口（`open/read/write/close`），屏蔽不同文件系统（ext4、FAT32、NTFS、NFS…）的差异。

```
用户程序
   │  open("/home/file.txt")
   ▼
VFS（统一接口层）
   │  ▼
   ├── ext4 驱动
   ├── FAT32 驱动
   └── NFS 驱动（网络文件系统）
```

### 文件系统挂载（Mounting）

将一个文件系统（分区）挂载到某个目录（挂载点）下，使其成为目录树的一部分。

```
挂载前：/mnt/usb 是一个空目录
挂载后：/mnt/usb 下显示 USB 盘的内容
```

命令：`mount /dev/sdb1 /mnt/usb`

## §10 外存空闲空间管理

| 方法 | 原理 | 优缺点 |
|------|------|--------|
| 空闲表 | 记录每段连续空闲区的（起始块号，长度） | 适合连续分配；碎片多时表很大 |
| 空闲链表 | 所有空闲块通过指针链接 | 简单；查找连续块慢 |
| **位图（Bitmap）** | 每个磁盘块对应 1 bit：0=空闲，1=已用 | 大小固定 = 总块数/8 字节；**最常考** |
| 成组链接法 | 将空闲块分组，每组首块存该组的块号列表 | Unix 使用，平衡效率与空间 |

**位图计算**：磁盘共 $N$ 块，位图大小 = $N/8$ 字节。

例：磁盘 1 GB，块大小 4 KB，共 $1\text{GB}/4\text{KB} = 256\text{K}$ 块，位图大小 = $256\text{K}/8 = 32\text{KB}$。

## §11 磁盘调度算法（大题手算必考）

### 磁盘访问时间

$$T_{\text{访问}} = T_{\text{寻道}} + T_{\text{旋转}} + T_{\text{传输}}$$

寻道时间最长（ms 级），是优化目标。

**平均旋转延迟** = 半圈时间 $= \dfrac{60}{2 \times \text{转速(rpm)}} \times 1000\ \text{ms}$

### 四种调度算法

| 算法 | 策略 | 特点 | 可能饥饿 |
|------|------|------|---------|
| FCFS | 按请求到达顺序服务 | 公平，但磁头乱跑效率低 | 否 |
| SSTF | 每次选最近磁道 | 平均寻道短，但边缘磁道可能饥饿 | **是** |
| SCAN（电梯）| 单方向扫到底再折返 | 综合性能好，无饥饿 | 否 |
| C-SCAN | 单向扫到底，直接回起点再扫 | 等待时间更均匀 | 否 |

### 手算步骤（SCAN / C-SCAN）

1. 确认磁头初始位置和移动**方向**（题目必须给出！）
2. 先服务当前方向上的所有请求（从近到远）
3. 到达最远请求后折返（SCAN）或直接回到最低磁道（C-SCAN）
4. 再服务反方向的所有请求
5. 总移动距离 = 各段 $|\text{目标} - \text{起点}|$ 之和

### 大题典型例题 4：四种算法手算对比

**题目**：磁盘磁道范围 $0 \sim 199$，磁头初始在磁道 **100**，向**高磁道**方向移动。磁盘请求队列（按到达顺序）：

$$\{55,\ 58,\ 39,\ 18,\ 90,\ 160,\ 150,\ 38,\ 184\}$$

分别用 FCFS、SSTF、SCAN、C-SCAN 计算服务顺序和总移动磁道数。

**解答**：

排序后的请求集合：$\{18, 38, 39, 55, 58, 90, 150, 160, 184\}$

---

**FCFS**（按到达顺序）：

$100 \to 55 \to 58 \to 39 \to 18 \to 90 \to 160 \to 150 \to 38 \to 184$

总距离：
$$|55{-}100|{+}|58{-}55|{+}|39{-}58|{+}|18{-}39|{+}|90{-}18|{+}|160{-}90|{+}|150{-}160|{+}|38{-}150|{+}|184{-}38|$$
$$= 45+3+19+21+72+70+10+112+146 = \mathbf{498}$$

---

**SSTF**（每次选最近）：

从 100 出发，请求集 $\{18, 38, 39, 55, 58, 90, 150, 160, 184\}$：

$100 \xrightarrow{10} 90 \xrightarrow{32} 58 \xrightarrow{3} 55 \xrightarrow{16} 39 \xrightarrow{1} 38 \xrightarrow{20} 18 \xrightarrow{132} 150 \xrightarrow{10} 160 \xrightarrow{24} 184$

总距离：$10+32+3+16+1+20+132+10+24 = \mathbf{248}$

---

**SCAN**（初始向高磁道，到达最高请求后折返向低）：

向高方向：$100 \to 150 \to 160 \to 184$（到顶折返）

向低方向：$184 \to 90 \to 58 \to 55 \to 39 \to 38 \to 18$

服务顺序：$100, 150, 160, 184, 90, 58, 55, 39, 38, 18$

总距离：$(184-100) + (184-18) = 84 + 166 = \mathbf{250}$

---

**C-SCAN**（向高扫到底，直接跳回 0，再向高扫）：

向高方向：$100 \to 150 \to 160 \to 184$（到达最高请求 184，直接返回 0）

从 0 向高扫：$0 \to 18 \to 38 \to 39 \to 55 \to 58 \to 90$

服务顺序：$100, 150, 160, 184,\ [跳回0],\ 18, 38, 39, 55, 58, 90$

总距离：$(184-100) + (184-0) + (90-0) = 84 + 184 + 90 = \mathbf{358}$

> ⚠️ C-SCAN 中从最高磁道跳回 0 的这段距离**要不要算**，取决于题目说明。有的题目认为这是"空行程"不计入，有的要计入，**一定要看题目条件**！

---

### 大题典型例题 5：磁盘访问时间计算

**题目**：磁盘转速 6000 rpm，平均寻道时间 8 ms，每道 100 个扇区，每扇区 512 B，求：
(a) 平均旋转延迟；(b) 数据传输率；(c) 读 1 个扇区的平均访问时间。

**解答**：

**(a) 平均旋转延迟**

转一圈时间 $= 60/6000 = 0.01\ \text{s} = 10\ \text{ms}$

平均旋转延迟 $= 10/2 = \mathbf{5\ \text{ms}}$

**(b) 数据传输率**

每圈数据量 $= 100 \times 512 = 51200\ \text{B} = 50\ \text{KB}$

转速 $= 6000/60 = 100\ \text{圈/s}$

数据传输率 $= 50\ \text{KB} \times 100 = \mathbf{5\ \text{MB/s}}$

**(c) 读 1 个扇区的平均访问时间**

传输 1 扇区时间 $= 10\ \text{ms} / 100 = 0.1\ \text{ms}$

$$T = T_{\text{寻道}} + T_{\text{旋转}} + T_{\text{传输}} = 8 + 5 + 0.1 = \mathbf{13.1\ \text{ms}}$$

## 附：大题常见题型汇总与答题要点

### 题型一：inode 访问次数计算
1. 算 $N = \text{块大小}/\text{块号大小}$
2. 划分各级范围（直接、一级、二级、三级）
3. 确定目标逻辑块号落在哪级
4. 访问次数 = 所处间接级数 + 1（数据块）[+ 1（若 inode 在磁盘）]

### 题型二：磁盘调度手算
1. 先排序请求集合
2. 确认磁头位置和初始方向（SCAN/C-SCAN 必须）
3. 按策略写出服务顺序
4. 逐段计算 $|\text{目标} - \text{当前}|$，求总和

### 题型三：硬链接/软链接辨析
- 硬链接 = 多个目录项指向**同一 inode**，不能跨文件系统，不能指向目录
- 软链接 = 独立 inode，内容是路径字符串，可跨文件系统，可指向目录，原文件删除后悬空

### 题型四：磁盘访问时间计算
1. $T = T_{\text{寻道}} + T_{\text{旋转}} + T_{\text{传输}}$
2. 旋转延迟平均 = 半圈时间
3. 传输时间 = 数据量 / 数据传输率

## 常见误区速查

| 误区 | 正确理解 |
|------|---------|
| inode 包含文件名 | inode **不含文件名**，文件名在目录项中 |
| 删除文件名即删除数据 | 只有 link count 归零时才真正释放数据块 |
| 连续分配没有碎片 | 连续分配有**外部碎片**（空闲区碎片化）|
| 软链接删除原文件后正常使用 | 原文件删除后软链接变为**悬空链接**，访问报错 |
| 硬链接可以跨文件系统 | 硬链接**不能跨文件系统**，软链接可以 |
| SSTF 一定优于 FCFS | SSTF 平均寻道短但可能导致边缘磁道**饥饿** |
| C-SCAN 比 SCAN 总移动距离短 | C-SCAN 等待时间更**均匀**，但总距离不一定更短 |
| inode 的二级间接访问 2 次即可 | 需要 3 次：读一级间接块 + 读二级间接块 + 读数据块 |

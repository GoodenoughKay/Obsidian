## §1 内存管理基础

### 逻辑地址 vs 物理地址

| 概念 | 含义 | 特点 |
|------|------|------|
| 逻辑地址（虚拟地址）| 程序编译后使用的地址，从 0 开始 | 每个进程独立，互不干扰 |
| 物理地址 | 内存条上真实存储位置 | 全系统唯一，进程不直接感知 |
| MMU（内存管理单元）| 硬件，运行时自动完成地址转换 | 对程序完全透明 |

```
CPU 发出逻辑地址 → MMU 转换 → 物理地址 → 访问内存
```

### 地址绑定的三个时机

| 时机 | 说明 | 是否支持重定位 |
|------|------|--------------|
| 编译时绑定 | 直接生成物理地址 | ❌ 只能加载到固定地址 |
| 装入时绑定（静态重定位）| 装入时一次性转换 | ✅ 装入前可选位置，装入后不可移动 |
| **运行时绑定（动态重定位）** | 每次访问时由 MMU 转换 | ✅ **现代 OS 采用**，支持虚拟内存和进程迁移 |

## §2 连续内存分配

### 碎片类型（必背）

| 碎片类型 | 产生场景 | 原因 |
|---------|---------|------|
| **内部碎片** | 分页（最后一页）、固定分区 | 分配的空间**大于**实际需求，多出的部分浪费 |
| **外部碎片** | 分段、动态分区 | 空闲空间**总量够**，但因不连续而无法使用 |

> 💡 **口诀**：内部碎片在分配块**里面**浪费，外部碎片在分配块**外面**（空闲区太零散）。

### 动态分区四种分配算法（选择题必考）

| 算法 | 策略 | 优点 | 缺点 |
|------|------|------|------|
| **首次适应（First Fit）** | 从头找第一个足够大的空闲块 | 速度快，保留大块 | 低地址区碎片多 |
| **最佳适应（Best Fit）** | 找最小的足够大的空闲块 | 减少大块浪费 | 产生大量极小碎片 |
| **最坏适应（Worst Fit）** | 找最大的空闲块 | 剩余块较大仍可用 | 大块很快耗尽 |
| **循环首次适应（Next Fit）** | 从上次分配位置继续找 | 均匀分配，减少低地址碎片 | 大块利用率下降 |

> ⚠️ **综合效果**：首次适应 ≈ 循环首次适应 > 最佳适应 > 最坏适应（实际系统多用首次适应）。

**解决外部碎片的方法**：**紧凑（Compaction）**——定期移动进程，合并空闲区。代价高，要求运行时绑定。

## §3 分页存储管理（大题核心考点）

### 核心思想

- 物理内存 → 等大的**页框（Frame）**
- 逻辑地址空间 → 等大的**页（Page）**
- 页大小 = 页框大小（通常 4 KB）
- 通过**页表**建立页号→页框号的映射

**碎片**：只有**内部碎片**（最后一页未填满），没有外部碎片。

### 地址结构

$$\text{逻辑地址} = \underbrace{\text{页号 } p}_{\text{高位}} \quad \underbrace{\text{页内偏移 } d}_{\text{低位}}$$

- 若页大小为 $2^k$ 字节，则低 $k$ 位为偏移，高位为页号
- 偏移位数 $k = \log_2(\text{页大小})$

### 地址转换公式

$$\text{物理地址} = \text{页表}[p].\text{页框号} \times \text{页大小} + d$$

**访存次数（无 TLB）**：
1. 访问页表（主存中）—— 1 次
2. 访问数据 —— 1 次
**共 2 次**

---

### 大题典型例题 1：分页地址转换手算

**题目**：系统页大小 1 KB，进程页表如下。将逻辑地址 2500（十进制）转换为物理地址。

| 页号 | 页框号 |
|------|--------|
| 0 | 5 |
| 1 | 3 |
| 2 | 8 |
| 3 | 2 |

**解答**：

**第一步**：页大小 $= 1\text{ KB} = 1024\text{ B} = 2^{10}$，低 10 位为偏移。

**第二步**：将逻辑地址分解：

$$p = \lfloor 2500 / 1024 \rfloor = 2, \quad d = 2500 \bmod 1024 = 452$$

**第三步**：查页表，页号 2 → 页框号 8

**第四步**：计算物理地址：

$$\text{物理地址} = 8 \times 1024 + 452 = 8192 + 452 = \mathbf{8644}$$

---

### TLB（快表）与有效访问时间（EAT）

**TLB**：CPU 内部的硬件缓存，存放最近访问的页表项（相联存储器，并行查找），命中速度极快。

| 情况 | 访存过程 | 总时间 |
|------|---------|-------|
| TLB 命中 | TLB（$\alpha$）+ 数据（$\beta$）| $\alpha + \beta$ |
| TLB 未命中 | TLB（$\alpha$）+ 页表（$\beta$）+ 数据（$\beta$）| $\alpha + 2\beta$ |

**EAT 公式**（设 TLB 命中率为 $h$，TLB 访问时间 $\alpha$，内存访问时间 $\beta$）：

$$\boxed{EAT = h(\alpha + \beta) + (1-h)(\alpha + 2\beta)}$$

> ⚠️ **踩坑**：无论是否命中，TLB 的访问时间 $\alpha$ **都要算**（先查 TLB 才知道有没有命中）。

---

### 大题典型例题 2：TLB 有效访问时间计算

**题目**：内存访问时间 200 ns，TLB 访问时间 10 ns，TLB 命中率 95%，求有效访问时间 EAT 及相比无 TLB 时的提升比例。

**解答**：

$$EAT = 0.95 \times (10 + 200) + 0.05 \times (10 + 400)$$

$$= 0.95 \times 210 + 0.05 \times 410 = 199.5 + 20.5 = \mathbf{220\text{ ns}}$$

无 TLB 时：$200 + 200 = 400\text{ ns}$

提升：$(400 - 220) / 400 = 45\%$

---

### 多级页表

**目的**：页表本身可能很大（32 位地址空间，4 KB 页，页表需 4 MB），多级页表使页表可以按需调入内存。

**二级页表地址结构（32 位，页大小 4 KB 为例）**：

$$\underbrace{p_1(10\text{ 位})}_{\text{一级页号}} \underbrace{p_2(10\text{ 位})}_{\text{二级页号}} \underbrace{d(12\text{ 位})}_{\text{页内偏移}}$$

**地址转换**（无 TLB，需 **3 次访存**）：

1. 查**一级页表** → 得到二级页表物理地址
2. 查**二级页表** → 得到数据页框号 $f$
3. 访问数据：$f \times 4\text{ KB} + d$

> ⚠️ **多级页表的权衡**：
> - 优点：页表按需分配，节省内存（二级页表页可以换入换出）
> - 缺点：访存次数增加（$n$ 级页表需 $n+1$ 次访存）

## §4 分段存储管理

### 核心思想

按程序**逻辑结构**划分：代码段、数据段、堆段、栈段……每段长度不等，有独立的编号。

**逻辑地址 = （段号 $s$, 段内偏移 $d$）**，是**二维**地址（分页是一维）。

### 段表

每段对应一个段表项，记录：

| 字段 | 含义 |
|------|------|
| 基址（Base）| 该段在物理内存中的起始地址 |
| 段长（Limit）| 该段的最大长度 |
| 权限位 | 读/写/执行权限 |

### 地址转换（必须先越界检查）

$$\text{步骤 1：越界检查：若 } d \geq \text{段表}[s].\text{段长} \Rightarrow \text{越界中断（段错误）}$$

$$\text{步骤 2：物理地址} = \text{段表}[s].\text{基址} + d$$

**访存次数（无快表）**：1 次访问段表 + 1 次访问数据 = **2 次**

### 分页 vs 分段（必背对比）

| 维度 | 分页 | 分段 |
|------|------|------|
| 划分依据 | 固定大小（物理视角）| 逻辑模块大小（程序员视角）|
| 地址结构 | 一维（页号+偏移）| **二维**（段号+偏移）|
| 碎片类型 | **内部碎片** | **外部碎片** |
| 共享与保护 | 难（不按逻辑划分）| **容易**（以段为单位）|
| 程序员可见 | 透明（不可见）| 可见（程序员感知段的存在）|
| 大小 | 固定（OS/硬件决定）| 可变（由逻辑模块大小决定）|

## §5 段页式存储管理（高频考点）

### 核心思想

先按逻辑结构**分段**，再对每个段内部**分页**。综合两者优点：
- 分段的好处：逻辑清晰，便于共享和保护
- 分页的好处：消除外部碎片，物理内存管理简单

### 地址结构

$$\underbrace{\text{段号 } s}_{\text{高位}} \quad \underbrace{\text{段内页号 } p}_{\text{中间}} \quad \underbrace{\text{页内偏移 } d}_{\text{低位}}$$

### 数据结构

- **段表**：每段一项，记录该段的**页表起始地址**（指向该段的页表）
- **页表**：每段有自己独立的页表，记录段内页号 → 页框号

### 地址转换（无 TLB，需 **3 次访存**）

```
段号 s → 查段表（第1次访存）→ 得到该段的页表基址
段内页号 p → 查该段的页表（第2次访存）→ 得到页框号 f
物理地址 = f × 页大小 + d（第3次访存：访问数据）
```

---

### 大题典型例题 3：段页式地址转换手算

**题目**：段页式系统，页大小 4 KB，段表和页表如下。将逻辑地址（段号=1，段内页号=2，页内偏移=100）转换为物理地址，并说明需要几次访存（无 TLB，段表和页表均在内存）。

**段表**：

| 段号 | 页表基址 |
|------|--------|
| 0 | 3000H |
| 1 | 4000H |
| 2 | 5000H |

**段 1 的页表**（基址 4000H）：

| 段内页号 | 页框号 |
|---------|-------|
| 0 | 10 |
| 1 | 15 |
| 2 | 7 |
| 3 | 20 |

**解答**：

**第一步**：用段号 $s=1$ 查段表

→ 段 1 的页表基址 = 4000H（**第 1 次访存**）

**第二步**：用段内页号 $p=2$ 查段 1 的页表

→ 页框号 $f = 7$（**第 2 次访存**）

**第三步**：计算物理地址

$$\text{物理地址} = 7 \times 4096 + 100 = 28672 + 100 = \mathbf{28772}$$

（**第 3 次访存**：访问物理地址 28772 处的数据）

**共需 3 次访存。**

---

### 段页式 vs 纯分页 vs 纯分段（三方对比）

| 维度 | 纯分页 | 纯分段 | 段页式 |
|------|--------|--------|--------|
| 碎片 | 内部碎片 | 外部碎片 | 内部碎片（同分页）|
| 地址空间 | 一维 | 二维 | 二维 |
| 共享与保护 | 较难 | 容易 | 容易 |
| 无 TLB 访存次数 | **2 次** | **2 次** | **3 次** |
| 实现复杂度 | 中等 | 中等 | 复杂 |
| 实际应用 | 主流 | 少（Unix 段）| x86 保护模式 |

> ⚠️ **最高频考点**：段页式无 TLB 时访存 **3 次**（段表 + 页表 + 数据），纯分页或纯分段是 **2 次**。加入 TLB 后若命中，均只需 **1 次**（直接访数据）。

---

### 答题步骤模板（地址转换大题）

**分页**：
1. 偏移位数 $k = \log_2(\text{页大小})$
2. 页号 $p = \text{逻辑地址} \gg k$，偏移 $d = \text{逻辑地址} \bmod 2^k$
3. 查页表得页框号 $f$，物理地址 $= f \times 2^k + d$

**分段**：
1. 逻辑地址 = (段号 $s$, 偏移 $d$)
2. 查段表：**先越界检查**（$d \geq$ 段长 → 段错误）
3. 物理地址 $=$ 基址 $+ d$

**段页式**：
1. 逻辑地址 = (段号 $s$, 段内页号 $p$, 偏移 $d$)
2. 查段表 → 得到该段页表基址（访存 1）
3. 查该段页表 → 得到页框号 $f$（访存 2）
4. 物理地址 $= f \times \text{页大小} + d$（访存 3，数据）

## §6 虚拟内存基本概念

### 为什么需要虚拟内存

物理内存有限，但程序的逻辑地址空间可以比物理内存大得多。虚拟内存的核心思想：**程序不需要全部装入内存就可以运行**，只将当前需要的部分装入，其余暂放在磁盘上（交换区 / Swap）。

### 三个特性

| 特性 | 含义 |
|------|------|
| **多次性** | 程序可以分多次调入内存，不必一次装入全部 |
| **对换性** | 允许程序在内存和磁盘之间换进换出 |
| **虚拟性** | 逻辑地址空间可以比物理内存大（用磁盘扩充）|

### 局部性原理（虚拟内存的基础）

- **时间局部性**：刚访问过的地址，近期可能再次访问（循环体、函数调用）
- **空间局部性**：访问某地址，附近的地址也可能被访问（数组、顺序执行）

正是因为局部性原理，只把"近期用到"的部分装入内存就足够了。

## §7 请求页式管理

### 请求页表项（比普通页表项多出的字段）

| 额外字段 | 含义 |
|---------|------|
| **有效位（Present/Valid）** | 该页是否在物理内存中（=0 触发缺页中断）|
| **修改位（Dirty，D）** | 该页是否被修改过（换出时需写回磁盘则 D=1）|
| **访问位（Reference，R）** | 该页最近是否被访问过（用于 Clock 算法）|
| 外存地址 | 该页在磁盘上的存放位置 |

### 缺页中断处理过程

1. CPU 访问某虚拟地址，MMU 查页表发现有效位 = 0
2. 硬件产生**缺页中断**（内部中断，Fault 类型）
3. 操作系统保存现场，查找该页在磁盘上的位置
4. 选择一个页框（若内存满则先置换一页，见已有文件）
5. 从磁盘读入该页到选中的页框（磁盘 I/O，耗时最长）
6. 更新页表项（有效位置 1，填入页框号）
7. 恢复现场，**重新执行**引发缺页的那条指令（Fault 的特征）

> ⚠️ **缺页中断的类型**：缺页中断是由 CPU 内部 MMU 触发的**内部中断（异常，Fault 类型）**，不是外部 I/O 中断。处理完后**重新执行**出错指令（不是执行下一条）。

### 有效访问时间（含缺页）

$$EAT = (1 - p) \times t_{\text{mem}} + p \times t_{\text{fault}}$$

其中 $p$ 为缺页率，$t_{\text{mem}}$ 为正常访存时间，$t_{\text{fault}}$ 为缺页处理时间（主要是磁盘 I/O，ms 量级）。

## §8 页框分配与工作集/抖动

### 页框分配策略

| 策略 | 说明 |
|------|------|
| **固定分配** | 进程创建时分配固定帧数，运行中不变 |
| **可变分配** | 根据缺页率动态调整帧数 |
| **局部置换** | 缺页时只从自己的帧中选换出页 |
| **全局置换** | 缺页时可从所有进程的帧中选换出页（Linux 采用）|

> ⚠️ **最常用组合**：可变分配 + 全局置换（效率高，但某进程可能抢占其他进程的帧）。

### 抖动（Thrashing）

**定义**：进程分配到的帧数少于其工作集大小，频繁缺页，大量时间消耗在磁盘 I/O，CPU 利用率骤降的现象。

**恶性循环**：
$$\text{帧数不足} \to \text{频繁缺页} \to \text{进程等 I/O} \to \text{CPU 闲置} \to \text{OS 增加进程} \to \text{帧数更少} \to \cdots$$

**预防/解决方法**：

| 方法 | 原理 |
|------|------|
| **工作集模型** | 监控每进程的工作集大小，确保分配帧数 ≥ 工作集 |
| **缺页频率（PFF）控制** | 缺页率过高 → 增加帧数；缺页率过低 → 减少帧数 |
| **降低多道程序度** | 挂起部分进程，给剩余进程更多帧 |

### 工作集（Working Set）

进程在某段时间窗口 $\Delta$ 内访问的页面集合。

$$W(t, \Delta) = \{\text{在时间} (t-\Delta, t] \text{内访问过的页面集合}\}$$

工作集大小随时间变化，它反映了进程当前的局部性特征。操作系统确保每个进程分配的帧数 ≥ 其工作集大小，即可避免抖动。

## §9 内存映射文件

**内存映射文件（Memory-Mapped Files）**：将磁盘文件的一部分或全部直接映射到进程的虚拟地址空间，之后对该段地址的读写即是对文件的读写，由 OS 负责在需要时从磁盘换入。

**优点**：
- 文件 I/O 转化为内存访问，速度快（避免 read/write 系统调用）
- 多进程映射同一文件时，可共享物理页（如共享库 `libc.so`）
- 支持大文件的随机访问

**Unix/Linux 系统调用**：`mmap()`；Windows：`CreateFileMapping()`

## 附：各管理方式地址转换访存次数汇总

| 管理方式 | TLB 情况 | 访存次数 |
|---------|---------|---------|
| 纯分页（一级页表）| 无 TLB | **2 次**（页表 + 数据）|
| 纯分页（一级页表）| TLB 命中 | **1 次**（数据）|
| 纯分页（两级页表）| 无 TLB | **3 次**（一级 + 二级 + 数据）|
| 纯分段 | 无快表 | **2 次**（段表 + 数据）|
| **段页式** | 无 TLB | **3 次**（段表 + 页表 + 数据）|
| **段页式** | TLB 命中 | **1 次**（数据）|

## 常见误区速查

| 误区 | 正确理解 |
|------|---------|
| 分页没有碎片 | 分页**有内部碎片**（最后一页未填满），无外部碎片 |
| 分段没有碎片 | 分段有**外部碎片**（不连续空闲区），无内部碎片 |
| 段页式访存 2 次 | 段页式无 TLB 时访存 **3 次**（段表 + 页表 + 数据）|
| 逻辑地址就是偏移量 | 逻辑地址是**完整地址**（包含页号+偏移），偏移是其低位部分 |
| TLB 未命中时不需要查 TLB 时间 | TLB 访问时间 $\alpha$ **无论命中与否都要计算**（先查才知道结果）|
| 多级页表减少了页表项总数 | 多级页表不减少**项数**，减少的是**需常驻内存的页表项数** |
| 缺页中断是外部中断（I/O 中断）| 缺页中断是 CPU 内部 MMU 触发的**内部中断（Fault）**，处理后重新执行出错指令 |
| 越界检查在分页中也有 | 越界检查主要在**分段**中进行（段长限制）；分页的越界体现在页表有效位 |
| 虚拟内存 = 磁盘当内存 | 虚拟内存是**地址空间抽象**，磁盘是存放暂时不用的页的地方，两者不同 |
| 工作集大 → 抖动严重 | 工作集大只是意味着进程需要更多帧；**帧数 < 工作集大小才导致抖动** |

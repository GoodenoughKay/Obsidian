# 深度解构：堆排序 (Heap Sort) 与 优先队列 (Priority Queue)

---

## 0x01 底层定义与逻辑推导

> [!ABSTRACT] 核心定义
> 
> **堆 (Heap)** 是一种满足特定性质的**完全二叉树**。
> 
> 1. **结构性质**：必须是完全二叉树（Complete Binary Tree）。
>     
> 2. **堆序性质**：
>     
>     - **大根堆 (Max-Heap)**：$L(i) \ge L(2i)$ 且 $L(i) \ge L(2i+1)$。
>         
>     - **小根堆 (Min-Heap)**：$L(i) \le L(2i)$ 且 $L(i) \le L(2i+1)$。
>         
> 
> **数学逻辑**：堆排序通过维护一个动态集合的偏序关系，将搜索最大/最小元素的时间复杂度从 $O(N)$降低至 $O(1)$，并将调整代价控制在 $O(\log N)$。

---

## 0x02 物理内存模型与映射

由于堆是完全二叉树，在 C++ 工业实践中，我们不使用链式存储，而是使用**顺序存储（数组）**以榨取 CPU 缓存性能。

### 内存布局与下标转换

假设数组起始下标为 `0`：

- **父节点 (Parent)**：`i -> (i-1)/2`
    
- **左孩子 (Left Child)**：`i -> 2i + 1`
    
- **右孩子 (Right Child)**：`i -> 2i + 2`
    
- **最后一个非叶子节点**：`n/2 - 1`
    

### 物理内存对齐 (M3/ARM64 视角)

在 Apple Silicon M3 架构下，`std::vector` 的内存是连续分配的。M3 的 L1 Data Cache Line 为 **128 字节**。

- **内存连续性**：堆排序的 `siftDown` 过程跨度较大，随着树深增加，会频繁触发 Cache Miss。
    
- **对齐优化**：M3 拥有强大的分支预测器，但在处理 `if (child < n && a[child] < a[child+1])` 时，若数据高度随机，分支预测失败会导致流水线排空（Pipeline Flush）。

## 0x03 算法实现全索引

### 核心函数详解

|**函数名**|**功能描述**|**时间复杂度**|**空间复杂度**|
|---|---|---|---|
|`heapify` (Build Heap)|从最后一个非叶子节点向上线性建堆|$O(N)$|$O(1)$|
|`siftDown` (Adjust)|向下调整，维持堆性质（核心）|$O(\log N)$|$O(1)$|
|`heapSort`|排序全过程|$O(N \log N)$|$O(1)$|

### C++ 工业级实现 (适配 C++20)

C++

```
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

/**
 * @brief 向下调整堆
 * @param nums 引用传递，避免拷贝
 * @param n 堆的有效规模
 * @param i 当前待调整节点下标
 */
void siftDown(vector<int>& nums, int n, int i) {
    int largest = i; 
    int l = 2 * i + 1; // 左孩子
    int r = 2 * i + 2; // 右孩子

    // M3 分支预测优化点：尽量减少逻辑分支
    if (l < n && nums[l] > nums[largest])
        largest = l;

    if (r < n && nums[r] > nums[largest])
        largest = r;

    if (largest != i) {
        swap(nums[i], nums[largest]);
        // 递归或迭代调整后续子树
        siftDown(nums, n, largest); 
    }
}

/**
 * @brief 堆排序主逻辑
 */
void heapSort(vector<int>& nums) {
    int n = nums.size();

    // 1. 建堆 (Build Heap): O(N)
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(nums, n, i);
    }

    // 2. 提取元素 (Extract): O(N log N)
    for (int i = n - 1; i > 0; i--) {
        // 将当前最大的根节点交换到末尾
        swap(nums[0], nums[i]);
        // 缩小堆规模，重新调整根节点
        siftDown(nums, i, 0);
    }
}
```

## 0x04 性能边界与缺陷分析

### M3 架构下的实战表现

> [!TIP] 开发实战技巧
> 
> 1. **不稳定性**：堆排序是**不稳定**排序。在 408 考研中，若要求排序后相同元素的相对位置不变，切勿选择堆排序。
>     
> 2. **Cache 不友好**：相比于快速排序（Quick Sort）的局部性原理，堆排序在 `siftDown` 时会跳跃式访问内存（$i \to 2i$），在处理超大规模数据（超过 M3 L3 Cache 容量）时，性能逊于快排。
>     
> 3. **TLB Miss**：在大内存页下，堆排序的随机访问特性可能导致频繁的 TLB 缺失。
>

## 0x05 408 考研特化模块

### 命题陷阱分析

> [!FAILURE] 408 易错点陷阱
> 
> 1. **建堆复杂度证明**：考研常考“为什么建堆是 $O(N)$ 而非 $O(N \log N)$？”。
>     
>     - **结论**：$\sum_{h=1}^{\log N} \frac{n}{2^{h+1}} \cdot h \approx O(n)$。即底层节点多但移动距离短，顶层节点少但移动距离长。
>         
> 2. **小根堆排大到小**：
>     
>     - 要得到**升序**序列，必须建立**大根堆**。
>         
>     - 要得到**降序**序列，必须建立**小根堆**。
>         
>     - _陷阱点_：很多学生下意识认为小根堆对应升序。
>         
> 3. **比较次数计算**：在 `siftDown` 过程中，每一层最多需要比较 **2 次**（先左右孩子比，再与父节点比）。
>     

### 对比表：堆 vs 常用排序

|**算法**|**平均时间**|**最坏时间**|**空间复杂度**|**稳定性**|**考点**|
|---|---|---|---|---|---|
|**堆排序**|$O(n \log n)$|$O(n \log n)$|$O(1)$|不稳定|建堆过程、筛选次数|
|**快速排序**|$O(n \log n)$|$O(n^2)$|$O(\log n)$|不稳定|递归深度、枢轴选择|
|**归并排序**|$O(n \log n)$|$O(n \log n)$|$O(n)$|稳定|外部排序、内存消耗|

## 0x01 [任务 A] 初始建堆手算逻辑

> [!ABSTRACT] 计算核心
> 
> 408 考研标准：从最后一个非叶子节点 $i = \lfloor n/2 \rfloor$ 开始，由后往前执行 `siftDown`。
> 
> 本题 $n=8$，第一个调整节点为 $8/2 = 4$（即第 4 个元素，下标 3，对应值为 `82`）。

### 1. 物理层转逻辑层

初始数组：`[15, 09, 25, 82, 35, 64, 47, 20]`

对应的逻辑完全二叉树：

### 2. 逐步调整过程

- **Step 1 ($i=3$, 值 82)**：左孩子是 `20`。$82 > 20$，无需变动。
    
- **Step 2 ($i=2$, 值 25)**：孩子是 `64, 47`。最大孩子是 `64`。$25 < 64$，**交换**。
    
    - 序列变为：`[15, 09, 64, 82, 35, 25, 47, 20]`
        
- **Step 3 ($i=1$, 值 09)**：孩子是 `82, 35`。最大孩子是 `82`。$09 < 82$，**交换**。交换后检查子树，`09` 与其新孩子 `20` 比较，$09 < 20$，**再次交换**。
    
    - 序列变为：`[15, 82, 64, 20, 35, 25, 47, 09]`
        
- **Step 4 ($i=0$, 值 15)**：根节点。孩子是 `82, 64`。最大孩子是 `82`。$15 < 82$，**交换**。
    
    - 交换后，`15` 与新孩子 `20, 35` 比较，与 `35` 交换。
        
    - 最终序列：`[82, 35, 64, 20, 15, 25, 47, 09]`

## 0x02 [任务 B] 删除堆顶（输出并调整）

> [!CAUTION] 408 陷阱点
> 
> 删除堆顶不是简单的删掉，而是**将堆底元素（序列最后一个）覆盖堆顶**，然后对新的堆顶执行一次 `siftDown`。

1. **输出 82**，将堆底 `09` 移至堆顶。
    
    - 当前状态：`[09, 35, 64, 20, 15, 25, 47]`
        
2. **向下调整 (siftDown)**：
    
    - `09` 的孩子是 `35, 64`。最大孩子是 `64`。
        
    - `09` 与 `64` 交换：`[64, 35, 09, 20, 15, 25, 47]`
        
    - 继续检查 `09` 的新孩子 `25, 47`。最大是 `47`。
        
    - `09` 与 `47` 交换：`[64, 35, 47, 20, 15, 25, 09]`
        

**最终结果**：新堆序列为 `[64, 35, 47, 20, 15, 25, 09]`。

## 0x03 考研必背对比：siftUp vs siftDown

在 408 算法题中，有时会涉及**插入**元素，此时用的是 `siftUp`。

|**操作**|**场景**|**复杂度**|**比较次数 (最坏)**|
|---|---|---|---|
|**siftDown**|初始建堆、删除堆顶|$O(\log n)$|$2 \times$ 树高|
|**siftUp**|插入新元素|$O(\log n)$|$1 \times$ 树高|

> [!FAILURE] 命题结论陷阱
> 
> 问：若给出一个已经排好序的升序数组，构建大根堆的时间复杂度是多少？
> 
> 答：依然是 **$O(n)$**。虽然数组有序，但 `heapify` 算法依然会从后往前扫描每个非叶子节点。不要被“有序”二字迷惑而选择 $O(n \log n)$。

## 0x04 Apple Silicon M3 指令级考量 (选读)

在 C++ 开发中，如果你使用 `std::priority_queue`，M3 的 **Neon 指令集** 可能并不会直接加速单次堆调整，因为堆操作是强依赖逻辑分支的。但是：

- **分支预测**：M3 的分支预测器对 `siftDown` 中 `if (a[l] > a[r])` 的判断有学习能力。如果数据具有局部单调性，速度会极快。
    
- **硬件预取**：由于堆是非连续跨步访问（$i \to 2i$），M3 的硬件预取器（Hardware Prefetcher）在树的前几层表现良好，但在底层（节点极多时）会失效。
